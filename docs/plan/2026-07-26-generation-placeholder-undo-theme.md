# CoreStudio 生成输入、占位生命周期与深色主题修复计划

> 状态：已完成
>
> 产品事实来源：`excalidraw/apps/image-board-desktop/PRODUCT.md` 与
> `excalidraw/apps/image-board-desktop/DESIGN.md`
> 日期：2026-07-26

## 目标

一次性修复 CoreStudio 内置生成链路的四个相互关联的问题：

1. 底部提示词输入框在粘贴或输入内容后可以使用 macOS `Command+Z` 和其他平台
   `Ctrl+Z` 撤销，React 状态同步不能破坏浏览器原生编辑历史。
2. 生成中和生成失败的画布占位是一个可一次删除的逻辑元素，不能先删除外框、
   再留下独立提示文字。
3. 用户删除生成中的占位后，该槽位立即失效；迟到的生成结果不能写入项目、
   进入素材记录，也不能在后续修复流程中重新出现在画布。
4. 图片素材入口、左侧素材详情、底部输入框和应用设置弹窗继承 Excalidraw 当前
   主题及既有 token，不新增 CoreStudio 自有深色配色。

## 当前事实

- 提示词输入框在每次 DOM 输入后重建 `contentEditable` 子节点，浏览器原生 undo
  栈因此失效。
- 生成占位使用 Excalidraw `frame` 加内部独立文字。上游删除 Frame 时会保留其
  子元素，这是合法的 Frame 语义，但不适合生成占位。
- 删除占位目前只改变 scene；生成任务、provider 请求和完成写回事务不知道该
  槽位已经被用户放弃。
- 返回图片目前会先持久化，再尝试替换占位。占位缺失时替换被跳过，但生成记录
  和文件已经进入项目，后续完整性修复可能把它重新加入画布。
- CoreStudio 的部分固定浮层位于 Excalidraw 主题根节点外，因而只读取到应用根
  节上的浅色 token；局部 hover 还存在硬编码浅色值。

## 已确认的产品语义

### 撤销

- 普通输入、粘贴以及浏览器原生 undo/redo 都只读取当前 DOM 并同步业务状态。
- 仅在外部状态确实改变编辑器内容或引用装饰时才重建 DOM。
- 修复不能吞掉 Excalidraw 画布的其他快捷键，也不能破坏中文输入法合成。

### 占位删除

- 生成占位使用普通容器与绑定文字，删除容器时由 Excalidraw 一次删除整组。
- 失败态沿用同一结构，不创建独立残留文字。
- 不修改上游 Frame 的“删除 Frame、保留子元素”行为。

### 任务与结果

- 删除一个生成中占位，只放弃对应槽位；同一批次的其他未删除槽位继续生成。
- 删除最后一个有效槽位时，CoreStudio 请求取消该 provider 任务。
- provider 是否能在服务端立即停止不是正确性的前提：被放弃槽位的迟到结果必须
  在项目写入前丢弃。
- 多图结果保持原始结果序号，删除前面的槽位不能让后面的结果错配。
- 删除失败占位时同步清理其任务标签，不触发 provider 取消。

### 深色主题

- CoreStudio 浮层保持原有 DOM 与布局作用域；一个不可见桥接点在 Excalidraw
  主题作用域内读取当前计算后的 `--island-bg-color`、
  `--text-primary-color`、`--default-border-color`、`--shadow-island`、
  `--color-primary` 等上游 token，并同步到应用根节点。
- 删除局部硬编码的浅色 hover/active 值，改用已有语义 token。
- 不复制 Excalidraw 深色调色板，不新增独立主题开关。

## TDD 与实施顺序

1. **输入框撤销**
   - 新增组件回归，证明受控状态回写时不再次替换用户刚编辑的 DOM。
   - 先确认测试在当前实现失败，再做最小 DOM 同步修复。
2. **占位一次删除**
   - 新增结构回归，要求普通容器、绑定文字及稳定槽位索引。
   - 先确认当前 Frame 结构失败，再替换占位构造方式。
3. **删除后的任务和结果**
   - 新增 scene reconciliation 回归：单槽位、多槽位、最后槽位、失败态和迟到
     结果。
   - 先确认当前任务注册表不会变化，再接入 App scene change。
   - 完成链路只处理注册表中仍有效的槽位，并在持久化前过滤结果。
4. **深色主题**
   - 新增 token 桥接与布局隔离回归。
   - 保持固定浮层原有 DOM 位置，透传 Excalidraw 当前计算后的主题 token，
     移除硬编码浅色状态。
5. **综合验证**
   - 运行直接测试、Desktop 全量测试、类型检查和生产构建。
   - 使用项目专属 Electron 启动方式和隔离 profile，真实检查浅色/深色、撤销、
     生成中删除、生成失败删除和多图局部删除。

## 非目标

- 不改变 Excalidraw 上游 Frame 删除语义。
- 不新增 provider 协议或假设远端一定支持硬取消。
- 不迁移或自动清理此前已经产生的孤儿图片记录。
- 不重做 CoreStudio 视觉系统。
- 初始实现阶段不擅自提交、打包、安装或发布；2026-07-27 用户已另行授权提交、
  推送与重新打包，仍不包含安装和公开发布。

## 完成标准

- 粘贴长文本后一次 `Command+Z` / `Ctrl+Z` 能恢复粘贴前内容，redo 仍可用。
- 生成中和失败占位只需一次删除，画布没有提示文字残留。
- 删除单个槽位后同批其他结果仍按原始顺序正确落位；删除全部槽位后发出取消请求。
- 所有被删除槽位的迟到结果在持久化前被丢弃，项目文件、生成记录和画布都不新增
  对应内容。
- 四个用户指出的 CoreStudio 界面在浅色和深色下均直接使用 Excalidraw token，
  hover、focus、disabled 和弹窗遮罩可读。
- 新增回归均经历先失败、后通过；全量自动验证和真实界面验收取得当前证据。
