# Wiki 操作手册

本页把 [`AGENTS.md`](AGENTS.md) 的规则转换为可执行步骤。

## 摄取一个仓库来源

1. 确认来源路径、文档状态、适用版本和最后更新时间。
2. 从 [`index.md`](index.md) 找可能受影响的主题页。
3. 阅读来源全文；对代码行为问题同时阅读相关测试或实现。
4. 把结论分为 `confirmed`、`proposal`、`observation`、`inference` 和 `unknown`。
5. 更新已有主题页；只有独立概念才新建页。
6. 在 [`sources/source-map.md`](sources/source-map.md) 登记新增来源。
7. 更新交叉链接和索引。
8. 在 [`log.md`](log.md) 追加 `ingest` 记录。
9. 运行相对链接、索引覆盖和 Git diff 检查。

## 摄取一个外部来源

1. 保存 URL、作者、标题、发布日期或访问日期。
2. 能合法保存且需要长期离线复核时，将不可变快照放入 `raw/`；否则只保存来源说明和外链。
3. 外部来源不得直接覆盖仓库 contract 或当前代码事实。
4. 只把与 CoreStudio 决策或理解直接相关的内容综合进主题页。
5. 明确标记外部观点、推断和本项目已经采纳的规则之间的差别。

## 回答一个问题

1. 先查索引，再读相关主题页。
2. 根据风险读取一手来源；运行状态和发布状态必须实时核验。
3. 先给结论，再给证据路径。
4. 说明哪些是已确认事实，哪些是提案、观察、推断或未知。
5. 默认不修改 Wiki。若答案具有长期复用价值，可向用户说明适合沉淀的位置。

## 执行一次体检

最小体检：

```sh
rg --files wiki
rg -n '\b(confirmed|proposal|observation|inference|unknown)\b' wiki
git diff -- wiki
git status --short
```

再用脚本检查所有本地 Markdown 链接是否存在，以及 `wiki/pages/**/*.md` 是否都被 `index.md` 引用。

人工检查：

- 是否出现两篇表达同一概念的页面；
- `confirmed` 是否有直接来源；
- 是否把旧计划写成了当前能力；
- 页面之间是否对同一边界给出不同答案；
- 最近变更是否要求更新来源地图、总览或术语表；
- 是否存在应该实时核验却写死的版本、端口、分支或发布状态。

## 沉淀一次查询

只有同时满足以下条件才写回：

- 结论跨任务、跨会话仍有价值；
- 有可引用来源，不只是聊天中的临时判断；
- 能更新现有主题页或形成可复用的新概念；
- 不属于密码、token、个人数据、临时路径或运行时秘密。

沉淀后按摄取流程更新索引、交叉链接和日志。
