# CoreStudio LLM Wiki

这是 CoreStudio 的可持续知识层。它把散落在代码、测试、稳定文档、规格和计划中的信息，编译成一组可检索、可交叉引用、可持续更新的 Markdown 页面。

本 Wiki 采用 Karpathy 提出的 LLM Wiki 模式：

1. **来源层**：仓库现有代码和文档，以及人工放入 [`raw/`](raw/README.md) 的不可变来源。
2. **综合层**：由 LLM 维护的主题页、总览、来源说明和索引。
3. **Schema 层**：[`AGENTS.md`](AGENTS.md) 规定证据状态、页面格式和摄取、查询、体检流程。

## 从哪里开始

- [总览](overview.md)：先建立对产品、架构和关键边界的整体认识。
- [索引](index.md)：按主题查找全部 Wiki 页面。
- [维护协议](AGENTS.md)：LLM 在读写 Wiki 前必须遵守的规则。
- [操作手册](operations.md)：摄取来源、回答问题和执行体检的方法。
- [来源地图](sources/source-map.md)：现有权威来源及其适用范围。
- [开放问题](pages/reference/open-questions.md)：尚未确认、待验证或容易漂移的事项。

## 使用方式

- **查询**：先读 `index.md`，再读相关主题页及其来源。回答默认不修改 Wiki。
- **摄取**：一次处理一个新增或发生实质变化的来源，更新受影响页面、索引和 `log.md`。
- **体检**：检查断链、孤立页面、证据漂移、互相冲突的结论和缺少主题页的重要概念。体检默认只报告，不自动改写。
- **沉淀**：只有可复用、跨会话仍有价值的分析才写回 Wiki；一次性调试结论留在任务记录或对应工程文档中。

## 边界

- `wiki/` 是 LLM 维护的综合层，不替代源码、测试、正式规范或发布记录。
- 仓库现有文件是只读来源；维护 Wiki 不得顺手移动、整理或改写它们。
- CoreStudio 项目数据由 CLI / Local Bridge 管理，不能把用户项目文件当作普通 Markdown 来源直接修改。
- Wiki 中的“已确认”只表示当前来源足以支持该结论，不保证未来版本永远不变。
