# CoreStudio 版本更新提醒方案

- 日期：2026-09-01
- 状态：已实现，待随官网清单发布
- 参考：FileBox 版本更新提醒第一版

> 本文是 CoreStudio 客户端版本更新提醒的单一规格来源。当前只做发现和引导，不包含应用内下载、自动安装或强制更新。

## 1. 目标

当稳定版发布后，旧版 CoreStudio 在正常使用过程中可以静默发现更新，并在“应用设置 → 关于”中提醒用户主动查看。用户仍通过官网或 GitHub Release 下载签名 DMG。

## 2. 产品边界

第一版包含：

- 官网静态托管 `https://getcorestudio.com/updates/stable.json`。
- 应用启动和再次激活时进行有节流的静默检查。
- 左上角画布菜单“关于与更新”、“关于”设置分类和“检查更新”按钮共享同一未读红点状态。
- 关于页手动检查，并内联展示新版、系统不兼容、已是最新或失败状态。
- 本机持久化最后尝试、最后成功、最后发现和最后查看的版本。
- 中英文文案、键盘操作和辅助技术可识别状态。

第一版不包含：

- 自动弹窗、系统通知或抢焦点。
- 画布、项目标签、图片生成输入框中的更新横幅。
- 应用内下载、自动安装、自动重启或强制升级。
- Beta、灰度、设备分群、更新埋点或远端控制开关。
- 直接读取 GitHub Releases API。

## 3. 与 FileBox 方案的适配

CoreStudio 复用 FileBox 已验证的静态清单、24 小时成功间隔、6 小时失败退避、自动检查静默和手动检查明确反馈。

CoreStudio 当前没有 FileBox 主窗口左下角的固定设置按钮，因此不新增常驻按钮。左上角现有画布菜单增加“关于与更新”快捷项，并与设置侧栏“关于”和关于页“检查更新”按钮共享红点；点击快捷项仍然进入同一个“应用设置 → 关于”页面。旧的独立“关于”弹窗以及原生“帮助 → 关于 / 查看更新”入口一并移除，避免维护多份内容。

CoreStudio 正式版本目前以 `package.json` / App bundle 的单一语义版本发布，不单独维护 build number。远端与本地按数字点分版本比较；将来正式引入独立 build 后再扩展清单 schema。

## 4. 用户路径

### 自动检查

1. 正式 App 创建主窗口或再次被激活。
2. 主进程判断检查间隔；同一进程只允许一个请求。
3. 请求稳定版清单并比较本地版本。
4. 有更新时持久化最新版本并广播未读状态；无更新静默结束。
5. 网络或清单错误只记录失败尝试，界面不提示。

成功检查后 24 小时内不再自动请求；失败后 6 小时内不重试。手动检查始终绕过间隔，并复用正在进行的请求。

### 手动检查

1. 用户进入“应用设置 → 关于”，点击“检查更新”。
2. 按钮进入检查中状态并暂时禁用。
3. 检查成功即把当前远端版本记为已查看并清除两级红点。
4. 有兼容更新时显示版本、最多三条摘要、“前往下载”和“查看更新说明”。
5. 新版要求更高 macOS 时只提供更新说明。
6. 无更新或失败显示简短内联结果，不弹窗。失败需区分网络连接、超时、服务未部署、服务不可用和清单格式异常，不得将 HTTP 错误统一归因为用户网络。

用户也可以从左上角画布菜单点击“关于与更新”直接进入同一设置页；Agent Board 不显示这个桌面应用入口。

## 5. 稳定版清单

```json
{
  "schemaVersion": 1,
  "channel": "stable",
  "version": "1.1.42",
  "publishedAt": "2026-08-25T14:20:45Z",
  "minimumSystemVersion": "14.0",
  "downloadPageURL": "https://getcorestudio.com/",
  "releaseNotesURL": "https://github.com/walnut-a/CoreStudio/releases/tag/v1.1.42",
  "asset": {
    "url": "https://github.com/walnut-a/CoreStudio/releases/download/v1.1.42/CoreStudio-1.1.42-arm64.dmg",
    "size": 122333386,
    "sha256": "4cf33cc80eabacd74eb2ac22db8ca9039817fff7ac2ce842e7b6d11a992a55ff"
  },
  "summary": {
    "zh-CN": ["…"],
    "en": ["…"]
  }
}
```

客户端使用 `schemaVersion`、`channel`、`version`、`publishedAt`、`minimumSystemVersion`、两个页面 URL 和摘要。`asset` 第一版只用于发布完整性合同，不触发下载。所有 URL 必须是 HTTPS，摘要每种语言最多消费三条。

清单是客户端发现稳定版的唯一远端事实源。官网仍可将下载按钮指向 GitHub Latest Release，但发版时必须先验证 Release 与 DMG，再更新清单并部署官网，避免先通知后可用。

## 6. 状态与权限

本机状态写入 CoreStudio 独立 `userData` 目录，只保存：

- `lastAttemptAt`
- `lastSuccessfulCheckAt`
- `lastKnownVersion`
- `reviewedVersion`

请求是无参数 HTTPS GET，不上传本地版本、系统版本、项目路径、设备标识、账号或使用行为。Agent Board 和 Local Bridge 不暴露更新检查 IPC。

## 7. 验收

- 远端版本高于本地时，自动检查只点亮两级红点，不打开窗口。
- 本地版本相同或更高时不显示红点。
- 点击设置分类不会清除红点；手动检查成功后才清除。
- 更高版本发布后红点重新出现。
- 自动失败静默且 6 小时退避；手动失败可重试并显示内联说明。HTTP 404 应提示服务未部署，只有请求无法建立时才提示网络连接。
- 同一时刻最多一个网络请求。
- 更新要求更高 macOS 时不显示下载主操作。
- 中文、英文和 VoiceOver 都能理解更新状态。
- 源码 Electron 中完成真实设置页验收；不以组件测试替代最终界面检查。
